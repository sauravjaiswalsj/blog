Week 2–3
Parent: Array traversal
Two
Pointers
Solves
Eliminate O(n²) nested loops on arrays by maintaining two indices that move toward — or away from — each other
Key Insight
Sorted order gives you a direction: sum too small → move left up. Sum too big → move right down. Each step eliminates half the remaining pairs.
Signal Keywords
sorted arraypair / triplet sumpalindromein-place removalcontainer / water
Sub-patterns
01 Opposite ends — pair sum
▼
Left pointer gives smallest, right gives largest. Move inward based on comparison.
// LC 167 — Two Sum II
int left = 0, right = numbers.length - 1;
while (left < right) {
    int sum = numbers[left] + numbers[right];
    if (sum == target) return new int[]{left+1, right+1};
    else if (sum < target) left++;
    else right--;
}
→ LeetCode 167
02 Three pointers — fix one, two-pointer the rest
▼
Sort. Fix i. Run two pointers from i+1 to end. Skip duplicates at all three levels or results repeat.
// LC 15 — 3Sum
Arrays.sort(nums);
for (int i = 0; i < nums.length - 2; i++) {
    if (i > 0 && nums[i] == nums[i-1]) continue; // skip dup
    int left = i + 1, right = nums.length - 1;
    while (left < right) {
        int sum = nums[i] + nums[left] + nums[right];
        if (sum == 0) {
            result.add(Arrays.asList(nums[i], nums[left], nums[right]));
            while (left < right && nums[left] == nums[left+1]) left++;
            while (left < right && nums[right] == nums[right-1]) right--;
            left++; right--;
        } else if (sum < 0) left++;
        else right--;
    }
}
→ LeetCode 15
03 Greedy opposite ends — maximise area
▼
Always move the pointer with the shorter height. Moving the taller one can only decrease area — never increase it.
// LC 11 — Container With Most Water
int left = 0, right = height.length - 1, maxWater = 0;
while (left < right) {
    int water = Math.min(height[left], height[right]) * (right - left);
    maxWater = Math.max(maxWater, water);
    if (height[left] < height[right]) left++;
    else right--;
}
→ LeetCode 11
04 Same direction — slow/fast
▼
Slow marks the write position. Fast scans. When fast finds a new value, write it at slow.
// LC 26 — Remove Duplicates
int slow = 0;
for (int fast = 1; fast < nums.length; fast++) {
    if (nums[fast] != nums[slow]) {
        slow++;
        nums[slow] = nums[fast];
    }
}
return slow + 1;
→ LeetCode 26
Gotcha
Requires sorted input for directional logic to hold. For 3Sum — skip duplicates at all three pointer levels or results repeat. For unsorted Two Sum — use HashMap.

Time: O(n)Space: O(1)

Parent: Divide and conquer on monotonic space
Binary
Search
Solves
Find a value in any monotonic search space in O(log n) — the space doesn't have to be a physical array
Key Insight
Every comparison eliminates half the space. Need a yes/no question where all "no" answers live on one side — a clean monotonic boundary.
Three Critical Details — Never Forget
Detail Why it matters
low <= high Handles the single-element case — without = you miss it
low + (high-low)/2 Prevents integer overflow on large inputs
mid ± 1 Prevents infinite loop when low == high
Sub-patterns
01 Classic — search sorted array
▼ 
int low = 0, high = arr.length - 1;
while (low <= high) {
    int mid = low + (high - low) / 2;
    if (arr[mid] == target) return mid;
    else if (arr[mid] < target) low = mid + 1;
    else high = mid - 1;
}
return -1;
→ LeetCode 704
02 Boundary find — first / last position
▼
Don't return when you find target. Record it. Keep narrowing. Return low at end — it converges to the boundary.
// LC 34 — Find First Position
int low = 0, high = arr.length - 1, result = -1;
while (low <= high) {
    int mid = low + (high - low) / 2;
    if (arr[mid] == target) {
        result = mid;
        high = mid - 1; // keep searching left
        // use low = mid + 1 for last position
    } else if (arr[mid] < target) low = mid + 1;
    else high = mid - 1;
}
return result;
→ LeetCode 34
03 Rotated sorted array
▼
One half is always sorted. Check which half. Determine which side target falls in. Eliminate the other.
// LC 33
while (low <= high) {
    int mid = low + (high - low) / 2;
    if (nums[mid] == target) return mid;
    if (nums[low] <= nums[mid]) { // left half sorted
        if (target >= nums[low] && target < nums[mid]) high = mid - 1;
        else low = mid + 1;
    } else { // right half sorted
        if (target > nums[mid] && target <= nums[high]) low = mid + 1;
        else high = mid - 1;
    }
}
→ LeetCode 33
04 Answer space — binary search on result
▼
No array to search. The answer itself is the search space. Ask: "is X feasible?" Yes/no answers form a monotonic boundary. Signal: "minimum speed / capacity / days".
// LC 875 — Koko Eating Bananas
int low = 1, high = Arrays.stream(piles).max().getAsInt();
while (low < high) { // converges to minimum answer
    int mid = low + (high - low) / 2;
    if (canFinish(piles, mid, h)) high = mid;
    else low = mid + 1;
}
return low;

boolean canFinish(int[] piles, int k, int h) {
    int hours = 0;
    for (int p : piles) hours += (p + k - 1) / k; // ceiling
    return hours <= h;
}
→ LeetCode 875

📍 Week 1 — Current focus
Parent: Recursion with state + undo
Back-
tracking
Solves
Explore all valid configurations in a decision tree — build candidates incrementally, abandon paths the moment a constraint is violated
Key Insight
Recursion explores. Backtracking explores and undoes. The undo step makes the same data structure reusable across all branches. Prune before recursing — eliminates entire subtrees.
The Three Structural Variables
Variable Controls Subsets Permutations Comb Sum
Start index Ordering i+1 0 i (reuse)
Loop start Exploration idx 0 idx
used[] Deduplication Not needed Required Not needed
Sub-patterns
01 Subsets — pure exploration
▼
Add current to result at every node. Loop from idx with i+1 — preserves order, no reuse.
// LC 78 — Subsets
void backtrack(int[] nums, int idx, List<Integer> cur) {
    result.add(new ArrayList<>(cur)); // snapshot ALWAYS
    for (int i = idx; i < nums.length; i++) {
        cur.add(nums[i]);               // choose
        backtrack(nums, i + 1, cur);   // explore
        cur.remove(cur.size() - 1);   // undo
    }
}
→ LeetCode 78
02 Subsets II — with duplicates
▼
Sort first. Skip nums[i] == nums[i-1] at the same recursion level only.
// LC 90 — Subsets II
Arrays.sort(nums);
void backtrack(int idx, List<Integer> cur) {
    result.add(new ArrayList<>(cur));
    for (int i = idx; i < nums.length; i++) {
        if (i > idx && nums[i] == nums[i-1]) continue;
        cur.add(nums[i]);
        backtrack(i + 1, cur);
        cur.remove(cur.size() - 1);
    }
}
→ LeetCode 90
03 Permutations — full loop + used[]
▼
Order matters so loop from 0 every call. used[] prevents picking same element twice in one path.
// LC 46 — Permutations
boolean[] used = new boolean[nums.length];
void backtrack(List<Integer> cur) {
    if (cur.size() == nums.length) {
        result.add(new ArrayList<>(cur)); return;
    }
    for (int i = 0; i < nums.length; i++) {
        if (used[i]) continue;
        used[i] = true;
        cur.add(nums[i]);
        backtrack(cur);
        cur.remove(cur.size() - 1);
        used[i] = false;
    }
}
→ LeetCode 46
04 Combination Sum — pruning on sum
▼
Pass i not i+1 to allow reuse. Sort then break when candidate exceeds remaining — prunes entire subtree.
// LC 39 — Combination Sum
Arrays.sort(candidates);
void backtrack(int idx, int remain, List<Integer> cur) {
    if (remain == 0) { result.add(new ArrayList<>(cur)); return; }
    for (int i = idx; i < candidates.length; i++) {
        if (candidates[i] > remain) break; // PRUNE
        cur.add(candidates[i]);
        backtrack(i, remain - candidates[i], cur); // i not i+1
        cur.remove(cur.size() - 1);
    }
}
→ LeetCode 39
05 N-Queens — constraint satisfaction
▼
One queen per row. Track columns + diagonals. Same diagonal = same (row-col). Anti-diagonal = same (row+col).
// LC 51 — N-Queens
Set<Integer> cols = new HashSet<>();
Set<Integer> diag = new HashSet<>();     // row - col
Set<Integer> anti = new HashSet<>();     // row + col

void backtrack(int row, char[][] board) {
    if (row == n) { result.add(construct(board)); return; }
    for (int col = 0; col < n; col++) {
        if (cols.contains(col) || diag.contains(row-col)
            || anti.contains(row+col)) continue; // PRUNE
        cols.add(col); diag.add(row-col); anti.add(row+col);
        board[row][col] = 'Q';
        backtrack(row + 1, board);
        board[row][col] = '.';
        cols.remove(col); diag.remove(row-col); anti.remove(row+col);
    }
}
→ LeetCode 51
Gotcha
Always new ArrayList<>(current) when adding to result — adding the reference gives you an empty list later. Prune before recursing, not after. i+1 vs i controls reuse. idx vs 0 controls ordering.
Complexity
Subsets: O(2ⁿ)Perms: O(n!)Space: O(n)
📍 Week 7–8 — Hardest pattern. Build systematically.
Parent: Recursion + memoisation / bottom-up table
Dynamic
Programming
Solves
Optimisation or counting problems where the answer to a larger problem is built from answers to smaller overlapping subproblems
Key Insight
Brute force recursion recomputes the same subproblems exponentially. DP stores each answer once. The trick: define (1) what the subproblem IS and (2) how it relates to smaller ones — the recurrence.
The DP Framework — 5 Steps Every Time
1
Define state
dp[i] means what exactly? Be precise. Vague state = wrong recurrence.
2
Base case
dp[0] = ? dp[1] = ? Base cases are wrong more often than the recurrence.
3
Recurrence
dp[i] = f(dp[i-1], dp[i-2], ...) — derive this from the problem definition.
4
Answer
Which dp value is the final answer? Often dp[n] but not always.
5
Optimise space
Often O(n) table → O(1) variables. Do this last, not first.
Sub-patterns
01 Linear 1D — Climbing Stairs
▼
Start here. dp[i] = ways to reach step i. dp[i] = dp[i-1] + dp[i-2]. It's Fibonacci.
// LC 70 — Climbing Stairs
int a = 1, b = 1;
for (int i = 2; i <= n; i++) {
    int temp = a + b;
    a = b; b = temp;
}
return b;
→ LeetCode 70
02 House Robber — pick or skip
▼
dp[i] = max rob up to house i. At each house: rob it (dp[i-2] + val) or skip (dp[i-1]).
// LC 198 — House Robber
int prev2 = 0, prev1 = 0;
for (int n : nums) {
    int curr = Math.max(prev1, prev2 + n);
    prev2 = prev1; prev1 = curr;
}
return prev1;
→ LeetCode 198
03 Coin Change — unbounded knapsack
▼
dp[i] = min coins to make amount i. Try all coins. Fill with amount+1 as "infinity".
// LC 322 — Coin Change
int[] dp = new int[amount + 1];
Arrays.fill(dp, amount + 1); // "infinity"
dp[0] = 0;
for (int i = 1; i <= amount; i++)
    for (int coin : coins)
        if (coin <= i)
            dp[i] = Math.min(dp[i], 1 + dp[i - coin]);
return dp[amount] > amount ? -1 : dp[amount];
→ LeetCode 322
04 LCS — 2D two sequences
▼
dp[i][j] = LCS of text1[0..i-1] and text2[0..j-1]. Match → extend diagonal. Mismatch → take best of two neighbours.
// LC 1143 — LCS
int[][] dp = new int[m+1][n+1];
for (int i = 1; i <= m; i++)
    for (int j = 1; j <= n; j++)
        if (text1.charAt(i-1) == text2.charAt(j-1))
            dp[i][j] = 1 + dp[i-1][j-1];
        else
            dp[i][j] = Math.max(dp[i-1][j], dp[i][j-1]);
return dp[m][n];
→ LeetCode 1143
05 Edit Distance — insert/delete/replace
▼
dp[i][j] = min ops to convert word1[0..i] to word2[0..j]. Match is free. Mismatch: 1 + min of 3 neighbours.
// LC 72 — Edit Distance
int[][] dp = new int[m+1][n+1];
for (int i = 0; i <= m; i++) dp[i][0] = i;
for (int j = 0; j <= n; j++) dp[0][j] = j;
for (int i = 1; i <= m; i++)
    for (int j = 1; j <= n; j++)
        dp[i][j] = w1.charAt(i-1) == w2.charAt(j-1)
            ? dp[i-1][j-1]
            : 1 + Math.min(dp[i-1][j-1],
                  Math.min(dp[i-1][j], dp[i][j-1]));
→ LeetCode 72

📍 Week 5 — Start here after Trees
Parent: Graph traversal
Graphs
BFS + DFS
Solves
Explore all nodes and edges — find paths, connected components, cycles, shortest paths
Key Insight
A graph can have cycles so you must track visited nodes or loop forever. BFS explores level by level — first time you reach a node = shortest path. DFS goes deep — use for components and cycles.
BFS vs DFS
Goal Use
Shortest path (unweighted) BFS
All paths / exhaustive DFS
Connected components Either (DFS simpler)
Cycle detection DFS with state array
Level-by-layer BFS
Sub-patterns
01 DFS — connected components
▼
For each unvisited land cell, DFS marks entire component as visited. Count how many times you start a DFS.
// LC 200 — Number of Islands
void dfs(char[][] grid, int i, int j) {
    if (i < 0 || i >= grid.length || j < 0 || j >= grid[0].length) return;
    if (grid[i][j] != '1') return;
    grid[i][j] = '0'; // mark visited in-place
    dfs(grid, i+1, j); dfs(grid, i-1, j);
    dfs(grid, i, j+1); dfs(grid, i, j-1);
}
→ LeetCode 200
02 BFS — shortest path
▼
Mark visited BEFORE adding to queue — not after polling. Otherwise same node enters queue multiple times.
// BFS template
Queue<Integer> q = new LinkedList<>();
Set<Integer> vis = new HashSet<>();
q.offer(start); vis.add(start);
int steps = 0;
while (!q.isEmpty()) {
    int size = q.size();
    for (int i = 0; i < size; i++) {
        int node = q.poll();
        if (node == target) return steps;
        for (int nb : graph.get(node))
            if (!vis.contains(nb)) { vis.add(nb); q.offer(nb); }
    }
    steps++;
}
03 Cycle detection — directed graph
▼
Three states: 0 = unvisited, 1 = in current path, 2 = fully done. Cycle = reaching a node in state 1.
// LC 207 — Course Schedule
int[] state = new int[n];
boolean hasCycle(int node) {
    if (state[node] == 1) return true;
    if (state[node] == 2) return false;
    state[node] = 1;
    for (int nb : graph.get(node))
        if (hasCycle(nb)) return true;
    state[node] = 2;
    return false;
}
→ LeetCode 207
Gotcha
Mark visited BEFORE adding to queue — not after polling. Always check bounds before accessing grid. Disconnected graphs: outer loop over all nodes, not just node 0.

📍 Week 8 — Pairs naturally with Intervals
Parent: Locally optimal → globally optimal
Greedy
Solves
Optimisation problems where making the locally best choice at each step leads to the globally optimal answer — without exploring all combinations
Key Insight
Greedy works when local optimal never prevents a global optimal — the greedy choice property. The hard part is proving it. In interviews: identify the pattern, verify with one counterexample attempt, then code.
Greedy vs DP
Greedy DP
One pass, never revisit a choice Must consider all choices, build subproblems
Local optimal = global optimal Local optimal can harm global
O(n log n) or O(n) O(n²) or O(n×k)
Rule of thumb: try Greedy first. If a counterexample exists → DP.
Sub-patterns
01 Jump Game — track max reach
▼
If current index exceeds the furthest reachable index, return false. Update max reach at every step.
// LC 55 — Jump Game
int maxReach = 0;
for (int i = 0; i < nums.length; i++) {
    if (i > maxReach) return false;
    maxReach = Math.max(maxReach, i + nums[i]);
}
return true;
→ LeetCode 55
02 Interval scheduling — sort by end time
▼
Sort by end time. Greedily keep intervals that end earliest — leaves max room for the rest.
// LC 435 — Non-overlapping Intervals
Arrays.sort(intervals, (a, b) -> a[1] - b[1]); // sort by END
int count = 0, lastEnd = Integer.MIN_VALUE;
for (int[] iv : intervals) {
    if (iv[0] >= lastEnd) lastEnd = iv[1]; // keep
    else count++;                               // remove
}
return count;

Sort direction matters. Non-overlapping intervals → sort by end. Meeting rooms scheduling → sort by start. Getting this wrong gives the wrong answer silently.

Topological Sort — Kahn's Algorithm
Solves
Order nodes in a DAG so every edge u→v has u before v. Dependency ordering — prerequisite problems.
Key Insight
Start with nodes that have indegree 0. Process them, reduce neighbours' indegrees. When a neighbour hits 0, it's ready. If final count < total nodes → cycle exists.
// LC 207/210 — Course Schedule (Kahn's BFS)
int[] indegree = new int[n];
for (int[] pre : prerequisites) {
    graph.get(pre[1]).add(pre[0]);
    indegree[pre[0]]++;
}
Queue<Integer> q = new LinkedList<>();
for (int i = 0; i < n; i++) if (indegree[i] == 0) q.offer(i);

List<Integer> order = new ArrayList<>();
while (!q.isEmpty()) {
    int node = q.poll();
    order.add(node);
    for (int nb : graph.get(node))
        if (--indegree[nb] == 0) q.offer(nb);
}
return order.size() == n; // false = cycle
→ LeetCode 210
Union-Find — Disjoint Set
Solves
Efficiently track which elements belong to the same connected component — and merge components dynamically
Key Insight
Each component has a representative root. find(x) returns root. union(x,y) merges by connecting roots. Path compression + union by rank → nearly O(1) per operation.
class UnionFind {
    int[] parent, rank;
    UnionFind(int n) {
        parent = new int[n]; rank = new int[n];
        for (int i = 0; i < n; i++) parent[i] = i;
    }
    int find(int x) {
        if (parent[x] != x) parent[x] = find(parent[x]); // path compress
        return parent[x];
    }
    boolean union(int x, int y) {
        int px = find(x), py = find(y);
        if (px == py) return false; // already connected = cycle
        if (rank[px] < rank[py]) { int t = px; px = py; py = t; }
        parent[py] = px;
        if (rank[px] == rank[py]) rank[px]++;
        return true;
    }
}

Parent: Array / String traversal
Sliding
Window
Solves
Find optimal subarray or substring satisfying a condition — without recomputing overlapping work
Key Insight
Brute force recomputes every subarray. A window remembers what it processed. Expand right when valid, shrink left when constraint violated. State updates are O(1) per step.
Signal Keywords
subarray / substringlongest / shortestat most Kcontiguouswindow of size K
Fixed Window
int windowSum = 0;
for (int i = 0; i < k; i++) windowSum += arr[i];
int maxSum = windowSum;
for (int i = k; i < arr.length; i++) {
    windowSum += arr[i] - arr[i - k]; // slide
    maxSum = Math.max(maxSum, windowSum);
}
Variable Window
int left = 0, maxLen = 0;
Map<Character, Integer> map = new HashMap<>();
for (int right = 0; right < s.length(); right++) {
    map.merge(s.charAt(right), 1, Integer::sum);
    while (violatesConstraint(map)) {
        map.merge(s.charAt(left), -1, Integer::sum);
        if (map.get(s.charAt(left)) == 0) map.remove(s.charAt(left));
        left++;
    }
    maxLen = Math.max(maxLen, right - left + 1);
}
Gotcha
Window length = right - left + 1. Use while not if to shrink. Never let left pointer go backward — use max(left, ...) when jumping by index.

Prefix
Sum
Solves
Answer multiple subarray sum queries in O(1) after O(n) preprocessing — eliminates repeated summation
Key Insight
Sum of [i,j] = prefix[j+1] - prefix[i]. Precompute once. Any range query is one subtraction. With HashMap: finds subarrays summing to K in O(n).
Template
// Count subarrays with sum == K (LC 560)
Map<Integer, Integer> map = new HashMap<>();
map.put(0, 1); // CRITICAL — handles subarrays from index 0
int sum = 0, count = 0;
for (int x : nums) {
    sum += x;
    count += map.getOrDefault(sum - k, 0);
    map.merge(sum, 1, Integer::sum);
}
return count;
Gotcha
Always initialise map with (0, 1) — handles subarrays starting at index 0. Prefix array is size n+1, not n.

Parent: Trade space for time
Hashing
Solves
Collapse O(n²) nested loops to O(n) by storing previously seen values for O(1) lookup
Key Insight
Whenever you write a nested loop to "find something seen earlier", a HashMap eliminates the inner loop entirely. Store what you've seen. Look up what you need in O(1).
Templates
// Complement lookup (Two Sum)
Map<Integer, Integer> map = new HashMap<>();
for (int i = 0; i < nums.length; i++) {
    int comp = target - nums[i];
    if (map.containsKey(comp)) return new int[]{map.get(comp), i};
    map.put(nums[i], i); // AFTER lookup
}

// Group by property (Anagrams)
Map<String, List<String>> groups = new HashMap<>();
for (String w : strs) {
    char[] ch = w.toCharArray(); Arrays.sort(ch);
    groups.computeIfAbsent(new String(ch), x -> new ArrayList<>()).add(w);
}

Parent: Problem decomposition
Recursion
Solves
Problems expressible as a smaller version of themselves — reduce to base case, trust the recursion
Key Insight
Define the function's contract. Trust it. Only handle: (1) base case, (2) current step, (3) how to combine. The call stack handles the rest. Never trace every call mentally.
Three questions before any recursive function
1
What is my base case?
When do I stop? Missing this = stack overflow.
2
What does one call do?
What is the contract of this function?
3
How do I get from n to n-1?
What smaller input do I recurse with?
Template
int fib(int n) {
    if (n <= 1) return n;        // base case
    return fib(n-1) + fib(n-2);  // trust + combine
}
Gotcha
Missing or wrong base case = stack overflow. Don't trace every call. Define the contract precisely and trust it.
Parent: Recursion on hierarchical structure
Trees
Solves
Hierarchical data problems — paths, depths, ancestors, serialization, level-order traversal
Key Insight
A tree is a graph with no cycles. Every tree problem is a recursion problem. Ask: do I need information from children first (post-order) or from parent first (pre-order)?
Traversal Templates
// DFS — Pre-order (root → left → right)
void preorder(TreeNode node) {
    if (node == null) return;
    process(node);          // root first
    preorder(node.left);
    preorder(node.right);
}

// DFS — Post-order (left → right → root)
int postorder(TreeNode node) {
    if (node == null) return 0;
    int left = postorder(node.left);
    int right = postorder(node.right);
    return combine(left, right, node); // root last
}

// BFS — Level order
Queue<TreeNode> q = new LinkedList<>();
q.offer(root);
while (!q.isEmpty()) {
    int size = q.size();
    for (int i = 0; i < size; i++) {
        TreeNode node = q.poll();
        if (node.left != null) q.offer(node.left);
        if (node.right != null) q.offer(node.right);
    }
}
